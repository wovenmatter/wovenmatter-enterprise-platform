# Managed knowledge workspaces

The platform provides invite-only accounts, each with independent admin/member memberships in multiple organizations. The owner creates organizations. Organization admins and the owner create projects and manage organization membership, project access and password-reset delivery. Removing membership revokes that organization's access, not the person's other memberships. Billing is outside the product.

Organization library access is per membership: ordinary members default to read-only; full access enables ordinary file management, sharing, moves and copies without granting administration. Existing explicit file grants and live organization-to-project shares remain supported. Shared content stays live; the share's read-only mode is a strict runtime boundary. Independent copies are ordinary files in their destination. Project-to-library moves/copies require both source and destination authority.

Each project has an always-on container and durable files, tool installations, native histories and schedule definitions. Different thread processes work concurrently in the shared workspace. One execution owns each thread. Cancellation/revocation stops that process and descendants; project deletion stops the project container. No idle stop or per-run container teardown occurs. Browser, API and supervisor attachment disconnects do not cancel admitted work. Completed turns retain native environments and intentional background processes. Stop also stops idle background work owned by that thread, preserving siblings; revocation tracks that ownership. Native history survives Stop. Process memory does not survive project/service restarts; unfinished work is reported interrupted/uncertain and is never silently replayed. Durable event cursors and API acknowledgments support reconnect without duplicate transcript effects.

Threads are private until a participant invites another eligible project user. Every participant can invite; participants are not individually removed. Creation mode is fixed. A read-only project user invited into a full thread intentionally directs full work inside that thread, without acquiring direct file, library or other-thread authority. Losing project or organization membership revokes the thread. A Message starts idle work or steers active work through the selected native integration. Comment never starts or steers and joins later context. Inputs retain authorship and server-received order. Native receipt uncertainty is visible and never automatically replayed.

Full project users ask the assistant to define scripts under `.wme/schedules`; there is no scheduling UI. Scripts have a private process boundary, durable interval receipts and project workspace access. When enabled, a separate project-scoped public HTTP/S capability allows unattended data refresh. It cannot authorize inference, private/host destinations or other sessions. Definitions survive restarts; interrupted work is not promised exactly-once execution.

Owner-only host defaults and creation overrides pin each project to a configured supervisor. A private Unix socket or mutually authenticated TLS carries authenticated requests. Remote filesystem access requires explicitly mounted shared storage verified by an on-demand probe. Placement changes do not relocate stored data. Additional physical host provisioning is an operator task, not an automatic service.

Reports at `/enterprise/reports/<id>` use only safe server-rendered HTML and fixed static images/SVG. A strict JSON contract selects current authorized data without publishing raw source documents. No custom HTML/CSS, browser scripts or generated server execution is accepted. Project visibility is the default; creators choose/change project, organization or public visibility, with administrator/owner override. Every resource checks access; public reports need no login.

Deleting a project immediately blocks access and stops runtime. Administrators can restore it or recover ordinary files into the organization library for 30 days. Expired trash is safely purged. Generic encrypted daily/off-host and pre-update backup/restore tools require operator-controlled quiescing and an explicitly supplied transport; no backup destination is selected by the software.

All inference is centrally managed per organization. Codex, Claude, Grok and Pi native integrations remain available with truthful capability errors. Provider credentials stay in separate organization services; employees select models without managing keys. Subscription terms and actual provider compatibility require operator review and separately authorized live acceptance.

React/TypeScript/Vite, Node 24/Fastify and worker-owned SQLite remain the stack. Fresh deployments create fresh data; migrations only keep baseline development schemas usable. No source-system state import, provider login, owner email or production provisioning is embedded in source. Full document extraction/OCR/indexing and specialized document pipelines are outside this change.
