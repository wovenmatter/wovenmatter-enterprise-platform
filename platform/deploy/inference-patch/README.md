# Structured remote subscription sign-in

This patch is applied only to CLIProxyAPI commit `acdace936fa7df2905500c7f5e0a97d683138dea`. The inference Dockerfile checks that pin, applies `upstream.patch`, copies the added Go files, runs their focused tests and builds the ordinary inference binary. No extra service or provider CLI is launched. Preserve the upstream MIT license and source attribution in `THIRD_PARTY_NOTICES.md`.

The added management routes run behind the existing management authentication middleware:

| Route under `/v8/management/oauth/remote` | Operation                                                                                   |
| ----------------------------------------- | ------------------------------------------------------------------------------------------- |
| POST (body: id, provider)                 | Admit an opaque UUID exactly once, return structured instructions                           |
| GET /:id                                  | Observe the receipt, never start another grant                                              |
| POST /:id/code                            | Submit one Anthropic manual code, with optional matching state fragment                     |
| POST /:id/commit                          | Persist a ready credential after Enterprise confirms current authority                      |
| DELETE /:id                               | Stop the attempt and remove its exact attempt-owned credential if saving raced cancellation |

OpenAI reuses `sdk/auth/codex_device.go` initiation, polling and token exchange helpers. The patch adds provider expiry, initial-interval/backoff handling and typed denial/expiry outcomes. Grok reuses `internal/auth/xai` device discovery/polling/storage, retaining its minimum interval and slow-down behavior. Anthropic reuses `internal/auth/claude` authorization, PKCE, exchange and storage with the provider-hosted manual redirect `https://platform.claude.com/oauth/code/callback`; it does not claim device-code support. This is also the manual redirect in the pinned Anthropic SDK 0.3.278. No localhost callback server or stdout scraping is involved.

References: [OpenAI authentication](https://learn.chatgpt.com/docs/auth), [Claude authentication](https://code.claude.com/docs/en/authentication), [Grok CLI reference](https://docs.x.ai/build/cli/reference). Device/remote protocol availability does not establish the user's entitlement or third-party subscription acceptance. OpenAI device login is beta and may require account/workspace security settings. The existing Claude notice remains required. Live approval is a human acceptance step.

The inference process owns provider work independently of HTTP/browser attachment. It keeps device identifiers, token responses and PKCE verifier in private memory, returns only the verification link/display code/deadline/flow, and never logs these handoff values. Calls and grants have bounded deadlines. Nonsecret, fsynced `.enterprise-signin/*.receipt` files fence replay across restarts and are excluded from normal credential scanners by extension. In-progress work becomes interrupted on inference restart; it is never resubmitted. A crash during save has an explicitly uncertain outcome; Enterprise cleans that exact attempt before retry.

The final save uses a UUID-owned private file, normal upstream storage, normal credential synthesis and the runtime registration hook. Completion follows file/directory sync and a durable receipt. Cancellation and save serialize; deleting a late result removes only that attempt, never an earlier connection. Deadline is rechecked around persistence. Enterprise records cancellation intent before its own long commit lane, verifies the initiating admin/session, and confirms cleanup before clearing the fence. Cleanup survives outages/restarts with bounded HTTP calls and capped backoff. While a cancellation remains unconfirmed, the organization's gateway fails closed and the attempt is omitted from account listings; unrelated organizations are unaffected. This is cleanup of a user-triggered sign-in, not a recurring application schedule.

Tests use injected HTTP transports and temporary storage only. They cover actual SDK protocols, interval/backoff/denial/expiry, code/state binding, no handoff-secret logging, management authorization, idempotent and conflicting admission, cancellation/save races, restart/corrupt-receipt fencing, private file permissions and each provider's synthesized runtime registration. Run `go test ./sdk/auth ./internal/api/handlers/management -run EnterpriseRemote -count=1` in the patched pinned source. The same selection runs during the image build; Go race checks are also appropriate. Test success is not live provider-account acceptance.

To update the patch, work from the exact pinned source, preserve formatting with gofmt, and regenerate a normal unified diff for the modified upstream files. The SDK transport setters are internal to the embedded bridge/tests; management clients cannot choose token endpoints or override transports. Do not loosen host allowlists, management authentication, Origin/CSRF checks or credential separation.
