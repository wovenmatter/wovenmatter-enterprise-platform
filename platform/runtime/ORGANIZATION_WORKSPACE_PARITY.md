## SDK and upgrade preservation

Native adapter dependencies are exact lockfile pins. Existing embedded Pi source and generations are not overwritten with native CLI adapters. Bundle fingerprints include the lockfile: operators must retain the entire approved-sdk/runtime-journal store when deploying, including generations pinned by existing chats. Never repoint existing generation IDs or delete old private native sessions. The inspected preview had no populated SDK generation or native session rows; populated upgrade behavior is covered independently by deterministic migration tests.

## Verification and limits

`native-harnesses.test.ts` exercises actual command/transport construction with strict deterministic ACP peers and a local OpenCode v2 service: root ordering, stream, settings, warm and cold resume, cancellation, approval/questions, exact usage and no uncertain replay. `native-forms.test.ts` tests typed conditional form behavior. `native-settings.test.ts` verifies authorization, connection catalog visibility, native model mapping and idempotent response receipts. Existing WorkspaceService tests cover reconnect/cursors/admission fences independently of individual native adapters.

The isolated Docker acceptance image contains the actual four pinned CLI executables plus embedded Pi. `check-container.sh` remains the full boundary gate; `native-selection-acceptance.mjs` can continue native-only checks on an exactly labeled retained synthetic allocation. Native-only checks do not establish kernel isolation. The first local full-container attempt stopped because the trusted host-listener positive control was refused before native execution; no firewall or host policy was changed. Synthetic tests never establish live provider entitlement or login compatibility. No external provider calls are used by acceptance fixtures.

On 2026-10-22, the clean production runtime image `sha256:e5e72c7d6994ee0a92c8b7571c345970dc03606ed6059750a1ed413c787a0349` passed actual Pi, Codex, Claude Code, Grok Build and OpenCode new-session, warm-resume and cold-process-resume turns against the synthetic gateway inside the restricted thread namespaces. Cold resume reopens private native history in the same image generation; this is not a cross-image SDK migration proof. Installed-adapter findings are covered by strict fixtures: Codex requires its private home to exist, standard ACP load can omit sessionId, Claude uses family aliases for exact gateway models, all JSON-RPC responses need version 2.0, and OpenCode needs authenticated PID-matched listener readiness after registration. All 37 focused protocol/form/settings/inference checks passed. A separate labeled host-network listener still reproduced the full boundary positive-control refusal, so the native pass does not waive that gate. Exact logs and synthetic native state are retained outside Git in the operator evidence directory. The refreshed lock inventory reports 526 occurrences/523 distinct package versions; the parent approved audit reported zero vulnerabilities.

The custom-provider follow-up preserves the desktop inherited Grok model configuration contract (`server.mjs` and `durable-acp.mjs`) using private per-session native TOML. Its fields follow the [native settings reference](https://docs.x.ai/build/settings/reference). `native-provider-acceptance.mjs` verifies all three Grok protocols and arbitrary organization model IDs for Codex and Claude, with actual pinned executables and new/warm/cold turns in a network-disabled container.
