# Persistent project runtime

The API assigns a project to one authenticated supervisor and provisions its container before reporting ready. `ProjectDockerRuntime` persists placement and allocation identities, creates an internal project network and managed volume subpaths, and retains the project container across runs and restarts. Only project deletion invokes its stop lifecycle. Purge removes only resources with matching allocation labels. Unknown resources are never adopted or removed.

A trusted root daemon inside the project container launches each thread process with independent bubblewrap mount, PID, IPC, UTS, user and network namespaces. It opens source and session components without following symlinks. Root-owned transient binds pin those descriptors; bubblewrap receives immutable sources without reopening user-controlled paths. The launcher drops outer UID/GID to 10001 before entering namespaces. The agent then has UID 10001, no capabilities, no-new-privileges, mandatory stacked `wme-platform-agent` and `wme-project-supervisor` AppArmor and a syscall filter. The trusted launcher's extra mount/namespace permissions never become agent permissions. The supervisor records each direct sandbox child's kernel start identity. Cancellation uses a pidfd-pinned helper under UID10001 and the existing trusted supervisor profile to signal only that owned child; it does not grant CAP_KILL or additional signal permissions to agents. Cleanup never recursively deletes a mount whose removal is uncertain.

All project threads see the shared workspace, with kernel-enforced read-only/full binds. Library share modes remain strict even in full threads. Each thread/harness/model/connection/mode gets its own persistent native state and home; other sessions and `/control` are absent. `/tmp` is private to a retained environment and lasts until that environment stops. Native history storage is independent of the disposable authority generation, so Stop does not erase history. Install reusable project tools under `/workspace/.tools`; its bin directory is on tool PATH. Root image and bundled document tools remain read-only. Process memory and active processes are not persisted across restart.

The project service owns native environments and background work, not an HTTP connection or an API process. One turn is admitted per thread; separate threads run concurrently. Codex app-server, Grok ACP, Claude's SDK query and Pi's SDK session remain available across ordinary completed turns. Failed transports are retired; only a new explicit request can resume their durable history. An API restart may interrupt an in-flight provider request through its inference gateway; the workspace records the actual native outcome and never resubmits the prompt. It does not promise uninterrupted upstream network connections. There is no separate Pi CLI adapter. Full collaborators deliberately share code and files; isolation does not protect users from shared code they choose to execute. Concurrent file edits have ordinary filesystem conflict behavior, without automatic merge or rollback.

Native shells may clean up their own tool subprocesses: use `wme-background start -- COMMAND [ARGS...]` for intentionally persistent work. It launches inside the existing thread namespace outside the tool's process group, records ownership under private `/session/background`, and discards stdout/stderr; write desired results/logs explicitly to files. `wme-background list` lists current environment jobs. A leader exiting does not prove all descendants exited. Each environment allows 64 explicit background launches; Stop retires that environment. Background processes keep working after a turn finishes and across attachment/API/supervisor disconnects. Thread Stop terminates all that thread's retained environments and descendants, including idle background work, while preserving siblings and the project container. Membership/share revocation fences stale admissions and stops affected thread environments before acknowledging revocation. Private native history remains recoverable. Container restart/deletion terminates all project processes; process memory, network connections and running services cannot survive it.

Admission identities, steering receipts, authority generations and ordered output live in a root-owned SQLite journal under the project control volume. Admission commits before the native write; an uncertain accepted prompt is never replayed. API/supervisor attachments reconnect by identity and cursor; replacing an attachment fences its steering authority. The API commits each transcript effect and cursor together, then explicitly acknowledges that cursor. A failed acknowledgment remains a durable retry outbox. Completed output is eligible for removal only after acknowledgment, under a 256 MiB replay budget and 30-day retention. Unacknowledged results remain recoverable; storage pressure rejects further output/admission truthfully rather than discarding them. Individual turns have a 16 MiB output limit, replay pages are bounded, and identity tombstones remain for the project's lifetime. On service/container restart, unfinished work becomes interrupted/uncertain without dispatching it again. Backup quiescence must include workspace services, their control-volume journals and native state as well as the API database; restoring files is not restoration of live process memory.

Thread tools have no direct network route. Private per-environment Unix sockets relay only scoped inference and optional public HTTP/S egress. The agent receives a stable local broker token, never the upstream capability. Inference authority is replaced for each admitted turn and cleared at its end; idle background work cannot initiate paid inference. Public HTTP/S uses the current project egress grant, which the trusted broker reloads for each connection. The proxy checks project/run authorization, current host/private destination exclusions, quotas and revocation. No provider or management secret enters the agent.

A Message steers active work through Codex `turn/steer`, Grok `_x.ai/interject`, Claude streaming input `priority: now`, or Pi native `streamingBehavior: steer`. Unsupported commands, lost receipts and ended-turn races produce explicit rejected/uncertain delivery. Claude consumed UUIDs establish which result finishes admitted work. Pi keeps its subscription through preflight and continuations. Initial delivery is acknowledged separately from process startup. Neither transport loss nor provider rejection automatically replays a prompt.

Native pins are unchanged: Codex CLI 0.158.0, Claude Agent SDK 0.3.278, Grok Build 1.0.41 (verified SHA256 in Dockerfile), Pi SDK 0.86.1. All four use centrally configured inference. Actual provider entitlement is separate from synthetic protocol acceptance. Native tools also require permission to signal their own children under the effective stacked profile, for cleanup and timeouts. The acceptance harness checks this independently of trusted platform Stop; passing the latter does not establish the former. Deployment must pass both checks under its installed policy.

Scheduled scripts use the file contract in [agent instructions](AGENTS.md). The trusted scheduler serializes scans and persists/fsyncs an admission timestamp before each execution. A running definition cannot overlap itself; missed intervals do not create a catch-up burst. Each script gets full workspace access in its own restricted namespace, current explicitly shared library mounts with their individual read-only/full limits, no other library files or native histories, and an optional project-scoped egress capability that cannot authorize inference. Changing or revoking a library share updates trusted scheduler policy and stops affected scheduled processes before acknowledgment. Workspace definitions cannot select additional data mounts. Removing the definition prevents subsequent admissions; deletion stops all project processes. An interrupted script is uncertain and is not retried immediately.

The runtime requires Linux amd64, Docker 26+ `volume-subpath`, AppArmor ABI 4 with stacked transitions, bubblewrap and namespace support. Managed roots and their parents must be operator-controlled. Failures of any kernel boundary fail closed. The persistent container's trusted launcher has a broader profile and disables Docker's default seccomp only to construct nested namespaces; the trusted outer container also uses systempaths=unconfined so locked Docker proc submounts do not prevent its fresh PID-namespace proc mount. Both profiles keep /proc/sys writes denied; the agent additionally denies sensitive proc reads and nested user namespaces. The agent always runs the dedicated mandatory filter, which rejects unshare/setns and namespace-bearing clone flags; clone3 returns ENOSYS for normal thread fallback. This design requires real kernel acceptance on the deployment kernel.

`WME_RUN_CONTAINER_ACCEPTANCE=1 bash platform/runtime/check-container.sh` is for a dedicated disposable Linux acceptance host. It verifies preinstalled policies, builds the exact image, uses only synthetic fixtures and records allocation identities for narrow cleanup. It never changes firewall rules. Do not run an unreviewed host-policy installer on a shared server. Node protocol tests and fake Docker driver tests do not establish kernel isolation, separately located host readiness, provider login, SMTP delivery or production deployment.

Capacity defaults allow eight active agent executions across the service and four per organization, with independent threads sharing each project. Each project container has a 4 GiB memory limit, four CPUs and 1024 process slots. Plan hosts for overlapping working hours, peak concurrency and headroom; measure actual workloads before changing these limits. Project availability is independent of idle time.
