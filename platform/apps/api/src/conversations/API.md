# Conversations

Root assembly creates the service with `createConversationService(ctx, { runtime, files: { resolveProjectMounts, reconcileProjectFiles, captureProjectManifest }, inference })`; inference supplies defaultHarness, validateSelection, issueGateway, and revokeGateway, registers `registerConversations(app, ctx, service)`, then calls `await service.start()` after all modules have migrated. Hook `ctx.onAccessChanged` into `service.recheckAccess()` and inference `canUseRun` into `service.canUseRun`. On shutdown call `service.close()` before closing the database.

Create: `POST /api/projects/:projectId/conversations` with `{title, mode:"read"|"write", model, harness?:"codex"|"claude"|"grok"|"pi", connectionId?}`. Model availability/compatibility checked centrally. Omitted or null harness defaults from the authoritative model catalog provider; OpenAI uses Codex, Anthropic uses Claude, xAI uses Grok, and OpenRouter/custom use Pi regardless of model-name prefix. PATCH null resets to that default; omitted harness preserves the current choice unless the model changes. Explicit connection preferences are only supported if inference supports them; the organization pool is the default.

Conversation responses: `{id,orgId,projectId,createdBy,title,mode,harness,model,connectionId,createdAt,updatedAt,activeRun,members}`. List uses `{items:[]}` and omits members. Creator changes settings/adds/removes collaborators and deletes the conversation. Adding collaborators requires current project access and never grants it. Every collaborator may message and cancel work. Every new turn uses the lesser of the conversation mode and the submitting member’s current project access. Read-only collaborators can send messages in full-access conversations; their agent turns receive read-only mounts and credentials bound to their own identity, never the creator’s authority. The admitted mode is fixed: a later upgrade never escalates an already queued turn, and a later downgrade can stop a previously admitted write turn. Creating or setting a full-access conversation still requires write access. Conversation detail and list include effectiveMode for the current viewer. Settings changes require an idle conversation.

Messages `POST /api/conversations/:id/messages` accepts `{content,requestId}`; request ID must be 8–100 URL-safe alphanumeric/underscore/hyphen characters (UUID recommended). Returns HTTP202 `{message,run,duplicate}` after SQLite admission. Duplicate same-user same-content requests return the original identity; conflicting reuse returns409. No model operation occurs before durable admission. Max100k-character messages, max50 queued turns per conversation. `GET .../messages?before=<messageId>` returns `{items,hasMore,nextBefore}` oldest-to-newest within the most recent200. Each message has `{id,conversationId,runId,role,authorId,authorName,content,citations,createdAt}`.

`GET .../runs` returns latest100 runs. Run: `{id,conversationId,userId,requestId,messageId,assistantMessageId,status,mode,harness,model,nativeSessionId,error,createdAt,startedAt,completedAt}`. Status queued/dispatching/running/cancelling/completed/failed/cancelled/interrupted. Per-thread execution is serialized by a database constraint and process dispatcher. `POST .../cancel` body `{runId?}` cancels the specified run or all queued/active runs.

SSE `GET .../events?after=<numericCursor>` (or Last-Event-ID header) emits named events with a persistent SQLite event ID. JSON `{id,conversationId,runId,type,data,createdAt}`. Types `run.queued`, `run.started`, `run.session`, `assistant.delta`, `tool.started`, `tool.completed`, `run.completed`, `run.failed`, `run.cancelled`, `run.interrupted`, `members.changed`. `assistant.delta` data `{messageId,delta}`; terminal data `{runId,messageId,error?}`. Clients may reconnect after their latest cursor, and refresh messages/runs for canonical state. Authorization rechecked each second. `access.revoked` terminates the stream. Slow clients are disconnected and can replay persisted events.

Restart: supervisor recovery kills any surviving containers, gateways are revoked, dispatching/running/cancelling records become interrupted. No uncertain model operation is replayed. Queued requests that were never dispatched may proceed. Native session IDs are persisted and completed same-harness/model/mode sessions resume. Switching harness rebuilds context from transcript (600k characters max, explicit error above bound). Current authorized mounts are resolved on every run; there is no release prerequisite. Active runs check permissions and shared-mount signatures each second and immediately on foundation's access hook.

Source references: optional files dependency `captureProjectManifest` snapshots available file IDs, paths, and immutable version IDs before each dispatch. `GET .../runs/:runId/sources` returns this availability manifest (`verification:available_at_dispatch`). Up to1000 references are included in the agent prompt; native tools still see all authorized files. Explicit normalized citation events and explicit `wme-file://<fileId>/<versionId>#page=N` references are admitted only against that run's known manifest. Assistant citations contain `{fileId,versionId,path,label,page?,verification:"source_reference",url}` and generate `assistant.citation` events. These are stable raw source references, not evidence that extraction or page-level verification occurred. Files changed during execution must not be represented as their old snapshot contents; the deferred extraction pipeline will provide verified page evidence. File download permission remains current, even for historical citations.

Runtime raw error messages are never returned to clients. Explicit failure codes remain visible, while uncertain transport failures are interrupted and require a deliberate new request. File metadata reconciliation runs after completion, cancellation, or uncertain failure; a reconciliation failure produces `files.reconciliation_failed` with a user-readable explanation. The native prompt is bounded to512KiB before dispatch. An oversized transcript gives an explicit prompt_too_large failure rather than silently discarding history.

If runtime cleanup cannot be confirmed, the run remains cancelling with `stop_not_confirmed`, emits `run.stopping`, and retains the conversation's execution lease. Maintenance retries the stop; following turns remain queued until the supervisor acknowledges cleanup. Gateway revocation and runtime stop are attempted independently, so a failed token-store operation cannot skip process termination. Restart recovery must succeed before queued work is accepted for execution.

API startup explicitly asks the supervisor to stop every durable active run, even if the supervisor itself did not restart. A cached supervisor recovery report is never treated as proof that current containers stopped. Any failed cleanup acknowledgment prevents startup from releasing those conversation leases. SSE connections are closed in Fastify preClose so graceful shutdown cannot hang on persistent browser streams.

Execution capacity is durable and global: by default at most8 runs across the installation and4 per organization may be dispatching, running, or cancelling. `WME_MAX_CONCURRENT_RUNS` and `WME_MAX_CONCURRENT_RUNS_PER_ORGANIZATION` map to AppConfig maxConcurrentRuns/maxConcurrentRunsPerOrganization (integer1–64). Tests may inject equivalent dependency options. A single atomic SQLite UPDATE…RETURNING chooses the oldest eligible queued run and checks both active counts, so simultaneous dispatch connections cannot oversubscribe capacity. Saturated organizations are skipped while other organizations have capacity; each conversation stays FIFO. Queued messages remain durable. Uncertain stopping leases continue consuming their slots until cleanup is acknowledged. Access checks are tracked independently per execution, preventing one stalled cleanup from delaying revocation on other active conversations.
