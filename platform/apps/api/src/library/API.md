# Assets and safe publication

All application, API and published paths start with `/enterprise`. Library offers **Files / Assets** and **New asset** in both views. An asset is a named draft with a description, editable content, a private preview and explicit publication. Organization admins/owners can create organization-owned drafts without a project. Full project members can create project-owned drafts. Ownership does not determine visibility: project assets default to project visibility; organization drafts default to organization visibility, but remain private until published. Organization-owned assets cannot use project-only visibility.

The accepted version 1 content document is specified in [agent instructions](../../../../runtime/AGENTS.md). Plain text is escaped; fixed templates render tables and SVG bar charts. Uploaded images are PNG/JPEG/WebP only. Arbitrary HTML, CSS, SVG input, scripts, forms, remote URLs and server entrypoints are rejected. Assets never run generated code.

- `GET /enterprise/api/organizations/:orgId/assets` lists accessible assets. Unpublished drafts are visible only to their current creator/admin managers. Other viewers see the published name/description, never unpublished edits.
- `POST /enterprise/api/organizations/:orgId/assets` accepts `{name,description?,projectId?,visibility?:"project"|"organization"|"public",document?:Report,sourceFileId?:string}`. Omit content to create an editable draft. Optionally supply one validated document or an authorized definition file. Creation stays private even when visibility is public. Programmatic callers can explicitly request `publish:true` for atomic creation and publication; the UI always creates a draft.
- `GET /enterprise/api/assets/:assetId` returns authorized metadata. Managers additionally receive draft content/revision and publication history; `canManage` and `canEdit` indicate current capabilities.
- `PATCH /enterprise/api/assets/:assetId` changes name, description, draft document/source file, or visibility. Draft changes require `expectedRevision`, plus full project or organization-library access. Visibility can be managed by a creator with current access, organization admin or owner. Published content stays unchanged until publication; visibility changes apply immediately.
- `POST /enterprise/api/assets/:assetId/publish` accepts `{expectedRevision,visibility?}`. It validates current sources and atomically snapshots a new numbered publication. A stale revision fails with conflict.
- `POST /enterprise/api/assets/:assetId/versions/:number/restore` accepts `{expectedRevision}`. It restores that publication into the draft after checking current source access. It does not silently publish.
- `DELETE /enterprise/api/assets/:assetId` immediately retires the asset and its link.
- `GET /enterprise/reports/:assetId/preview` renders the draft for a current manager only. It remains authenticated even for public assets.
- `GET /enterprise/reports/:assetId` renders the published definition using current authorized data. `GET .../images/:index` repeats visibility and source checks. Public publications need no login; organization publications require current membership; project publications require current project access. Unpublished URLs return not found.

A project asset can select only explicit values from current files in that project or its current library shares. An organization asset can use organization-library files only, even if its creator also administers projects. Every render/resource requires the creator to retain the relevant organization/project access. Removed membership, deleted project, unavailable source or revoked share fails closed. Historical versions do not freeze source bytes or bypass current permissions. No raw source-data endpoint is published. Already downloaded data cannot be recalled.

The atomic schema upgrade preserves existing published report IDs, URLs, visibility and definitions as publication 1 and an initial matching draft. File metadata/content are unchanged. Project trash retains its assets and versions; purge removes their versions with the asset. A pre-update database backup is required for an operator rollback to a release without the new schema.

Responses are no-store with restrictive CSP: sandbox, no scripts, forms, base URL or network connections. Fixed styles and validated inline data images are the only resources. Each render bounds source bytes to 8 MiB, each source to 4 MiB, content to 8 MiB and table cells to 100000. Reads are sequential, descriptor checked and cached for that render. Restoring asset creation does not restore executable app containers, arbitrary forwarding, generated HTML/CSS or asset-origin cookies.
