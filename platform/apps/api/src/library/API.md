# Library API

All administration routes require a signed-in user and normal CSRF headers. Organization assets require organization admin for editing. Project assets require current project write access; readers may list/view metadata. Assets never grant access to underlying project files.

- `GET /api/organizations/:orgId/assets?projectId=` → `{items: Asset[]}` (only accessible project assets + organization assets).
- `POST /api/organizations/:orgId/assets` `{name,type:'static'|'live',projectId?:string,description?:string}` → asset.
- `GET /api/assets/:assetId` → asset plus versions. `PATCH` accepts `{name?,description?}`. `DELETE` removes access immediately and stops a live runtime.
- `POST /api/assets/:assetId/resume` `{expectedVersionId:string}` → `{asset,version}` retries an existing live application after verifying current write authority and linked source identities. Healthy applications are confirmed without restarting. Normal API/host startup automatically resumes only current applications previously recorded as running whose existing container is stopped; failed or interrupted recovery becomes `needs_attention` with `runtimeError`. No automatic retry loop replays a failed recovery. Restored or replaced source folders require republishing.
- `POST /api/assets/:assetId/publish` accepts `{expectedVersionId:string|null,sourceFileId?:string,sourceVersionId?:string,files?:[{path:string,contentBase64:string}],entrypoint?:string,dataFileIds?:string[]}`. Exactly one of sourceFileId or files is required. Default static entrypoint `index.html`; live requires a relative `.js`/`.mjs`/`.cjs` Node HTTP entrypoint listening on `HOST`/`PORT`. Source is copied into a private immutable revision; file IDs authorize against the asset project. Raw bundles are bounded at 32 MiB / 1000 files. Live dependencies must be vendored or bundled into the source; publishing never installs arbitrary packages in the API process. `dataFileIds` selects **linked data folders**, mounted read-only at `/sources/<folderId>` for live apps only. Folder mounts observe atomic file replacements; direct individual-file mounts are rejected to avoid silently stale data. `/data` is a persistent per-asset writable filesystem, retained across publication and included in backups. Returns `{asset,version}`; version runtime status is explicit. Runtime failure is an error, never a fake running success. expectedVersionId prevents concurrent publication from silently replacing another revision.
- `GET /api/assets/:assetId/shares` → `{items: Share[]}`; existing tokens are not returned.
- `POST /api/assets/:assetId/shares` `{visibility:'public'|'organization'|'people',userIds?:string[],versionId?:string}` → `{share,url}`. Static links are pinned to an immutable published revision (current by default); live links follow the asset's current active revision. Only enabled members of the same organization may be selected. Share creation returns its bearer URL once. Private URLs require portal sign-in before access. Organization/share access is checked on each content request.
- `DELETE /api/assets/:assetId/shares/:shareId` → `{ok:true}`; existing content grants and streams are revoked.
- `GET /share/:token` is the visitor entry point. Public links work signed out. Private links require sign-in, then exchange a short-lived one-time ticket for an HttpOnly host-only content cookie. Generated HTML and applications are served only at the configured per-asset content origin, never on the portal origin. Root-relative routes work on that origin.

Asset: `{id,orgId,projectId,name,description,type,currentVersionId,createdAt,updatedAt}`. Version: `{id,assetId,number,entrypoint,manifestHash,sourceFileId,sourceVersionId,runtimeId,runtimeStatus,runtimeError,createdAt}`. Share: `{id,assetId,versionId,visibility,userIds,createdAt,revokedAt}`.

The backend needs `contentOriginTemplate`, e.g. `https://{orgSlug}-{assetId}.example.com`, a separate origin per asset, and a runtime host installed with `setLibraryRuntime`. Unconfigured hosting fails explicitly. Platform session credentials and share capabilities are stripped before forwarding requests to generated apps. App cookies are host-only and cannot override the reserved capability cookie. Applications run without platform or provider credentials.

The optional `{orgSlug}` is captured from the organization name when an asset is created, normalized to ASCII, and capped at 26 characters. Its UUID keeps each asset origin unique; renaming an organization does not change existing asset addresses. Configure wildcard DNS and ingress for the single-level content hostnames.
