# Controlled public-network proxy

Optional public internet access is isolated from the host, private networks and other containers. This module provides that boundary; startup, supervisor metadata, runtime environment and firewall integration must all be present before enabling it. The proxy port must never be published to the host or public ingress.

The isolated tests exclusively use injected DNS answers and injected sockets connected to local synthetic HTTP/TCP servers. They do not query public DNS, authenticate real accounts, or connect to public destinations.

## Interface

`createEgressProxy({authorize, excludedAddresses, excludedHostnames, getNetworkBoundary, limits?})` returns `listen(host,port)`, `close()` and secret-free `stats()`. The authorization callback is `InferenceService.authorizeGateway(projectId,runToken)`, which checks current run/project/user/thread permissions. No upstream provider or supervisor credentials are forwarded. Port 4101 is for the API container and isolated run network only, with no host publication or public reverse-proxy route.

Both exclusion arrays are mandatory. Addresses must contain at least one literal IP; each array is capped at 256 entries. Supply every host interface address, public NAT/ingress address and known host/application/asset hostname from trusted supervisor metadata and deployment configuration. This inventory is necessary because a host's public IP is otherwise indistinguishable from another public destination. Do not obtain the exclusions from an agent request. Excluded hostnames also exclude subdomains; case, IDNA, trailing DNS root dots and equivalent IPv6 spellings cannot bypass the comparisons. IPv4-mapped interface metadata also excludes the native IPv4 address. Every address in a mixed DNS response is checked before any connection is made.

Production must provide `getNetworkBoundary(): Promise<{addresses: string[], hostnames: string[]}>`, using authenticated supervisor metadata with at most five seconds of caching. It runs before new destination connections and during active authorization checks. Unavailable, malformed or timed-out metadata denies new requests and closes active connections. A newly excluded hostname or pinned destination address closes affected tunnels. Refreshed exclusions are retained until proxy restart; neither caller mutation nor removal from later metadata weakens the boundary. Cumulative address/hostname sets are capped at 4096 entries each and fail closed on overflow. Refreshes are deduplicated while in flight, including after a timeout, so stalled metadata requests cannot accumulate. The callback may be omitted only by isolated fixtures using a static inventory.

Proxy Basic authentication uses project ID as username and the existing short-lived run capability as password. The only protocols permitted by this implementation are absolute-URI HTTP on port 80 and CONNECT to ports 80 or 443. CONNECT80 is needed by Node.js 24 environment-proxy fetch for ordinary HTTP URLs; it uses the same authentication, destination exclusions, DNS pinning, resource limits and revocation checks as CONNECT443. It does not follow redirects. Each redirected request undergoes authorization and destination validation again. Arbitrary HTTP Upgrade is rejected; WebSocket over TLS can operate within an authorized CONNECT tunnel.

All A/AAAA addresses must be public global-unicast. Any private, loopback, metadata, link-local, documentation, multicast, mapped IPv6, translation or other excluded special-purpose address denies the request. Both A and AAAA lookups must finish conclusively. ENODATA is accepted as an absent family; timeout, SERVFAIL, cancellation and other failures deny the request, as does an inconsistent NXDOMAIN response alongside an address. DNS is resolved once and the selected literal address is pinned for connection establishment. Real resolvers are cancellable; outstanding resolution promises remain globally capped even if a test/custom resolver ignores abort.

Proxy credentials and hop-by-hop headers (including those nominated by `Connection`) are removed from forwarded HTTP requests. The Host header is set from the validated target. CONNECT transmits only tunnel bytes after authentication, never its proxy request headers. Ordinary destination authorization headers remain available for user-authorized external services.

Default bounds: 128 active operations, 8 per run, 4096 retained run budgets, 1 GiB total transferred payload/header bytes per run, 256 MiB per connection, 5-second DNS/auth deadlines, 10-second connect deadline, 60-second idle timeout and 15-minute connection lifetime. Active connections are reauthorized every second; loss of permission closes the entire run’s connections. Run usage remains counted after reconnects. Socket shutdown, late dial completion, pending DNS and proxy close are tested.

These tests validate the proxy module, not deployment firewall configuration, native-agent use of proxy environment variables, TLS-provider compatibility, or public-network behavior. Those acceptance checks must be performed separately on the integrated deployment before declaring production readiness.
